# 连续音频与免按键双向对讲设计

## 目标与前提

本规格承接厂商移植材料评估的第二阶段：接通每台门口机正式通话期间的连续音频播放，并在现有 HA 卡片中增加点击开启、再次点击关闭的全双工模式。用户已批准这一功能范围；本文将接口、资源上限和验收边界固定下来，供实现前审查。

- 浏览器麦克风仍要求 HTTPS 或 localhost 安全上下文和用户授权。HTTP 页面可以仅收听，不能声称支持麦克风或绕过浏览器限制。
- 音频控制只附着于已经建立的 `talking` 通话，不自动呼叫、接听或解锁。呼叫/接听/挂断沿用现有实体和服务。
- 继续只允许一个正式通话；多个预览的能力与行为不变。
- 不调整视频预览重试、设备冷却、门禁时序、通话保活或协议端口。
- 不部署证书、修改用户仪表盘、安装实机包或主动呼叫物理设备。安装与现场验收需要后续明确授权。

## 已有证据和当前缺口

实现基线为 Doorfast `1ab00eb`、Doorfast for HA `eae9767`（0.3.25）。本节描述已有代码，不代表新功能已经完成。

| 证据 | 现状 | 本阶段的改动方向 |
| --- | --- | --- |
| `src/runtime_service.c` 的 `df_runtime_receive_audio_payload` | 累积至少 8,000 个 A-law 样本，且距上次导出至少 1,000 ms 后才发布 WAV | 用约 100 ms 的小块替代秒级发布，限制积压 |
| `src/gvs_audio_buffer.c` | 接受顺序包，计数并丢弃重复/迟到包；没有有限乱序等待或丢包补偿 | 加入有界重排和短静音补偿，不改变真实包计数含义 |
| `src/gvs_audio_chunk_store.h` | 只保留四个按 revision 串联的音频文件 | 小块化后保留有界窗口，避免变成只有约 400 ms 的恢复余量 |
| HA `client.py` 的 `latest_audio_chunk` | 已验证 generation/revision，但游标属于整个 client；运行时没有扬声器消费者 | 复用校验逻辑，给连续播放建立独立、共享拉取的消费边界 |
| HA `frontend/audio-stream.mjs` 的 `PcmAudioPlayback` | 只有 `fetchChunk` / `playChunk` 回调；默认输出为空 | 接入真正的 Web Audio 输出和有限播放缓冲 |
| HA `frontend/doorfast-ptt-card.mjs` | 麦克风上行已经存在；扬声器只有外部注入钩子；默认是按住说话 | 接入下行，增加全双工和仅收听模式，保留原模式 |
| 厂商报告 19.2、19.3 与 `docs/gvs-audio-pcap-validation.md` | 通话音频有独立启停；入站 128/160/192 样本，上行 160 样本/20 ms；使用 A-law | 保持包格式、采样率和收发生命周期，不强制入站固定 160 字节 |

厂商报告来源为用户提供的 `portable-package/report/2026-10-12_gvs-intercom-portable-report.md`。已有抓包验证记录见 [GVS 音频验证](../../gvs-audio-pcap-validation.md)，协议基线见 [厂商移植材料基线](../../gvs-portable-package-baseline.md)。

## 方案选择

采用现有 G.711 / PCM 链路：门口机 UDP/8302 入站，经 Doorfast 解码与有界音频块，HA 通过已有认证 WebSocket 接口把 PCM 提供给浏览器。浏览器麦克风继续沿用现有 AudioWorklet、PCM producer 和 UDP 上行。

未选择的替代方案：

- 把音频并入 go2rtc / WebRTC 摄像头：可以统一音视频，但需要改变 RTSP 音轨和双向媒体信令，扩大目前已验证的视频链路风险，不在本阶段实施。
- 继续播放秒级 WAV 文件：改动较少，但每块等待时间过长，块间调度和延迟不能满足实时对讲，不作为最终方案。

下行使用请求/响应式拉取，而不是向 HA WebSocket 无限推送。每个浏览器最多一个读取请求在途；慢消费者不会积累无限事件队列。同一配置项共享一个串行的 Doorfast 拉取器，而不是每个浏览器独占全局 client 游标。

## Doorfast：有界接收与小块发布

### 接收重排和丢包处理

- 在既有源/目的地址与 generation 接纳检查之后，才进入音频重排；错误门口机的包不得进入缓冲。
- 新通话从第一包建立 16 位序号窗口，支持回绕。保存不超过四个待重排的真实包；等待缺口最长 40 ms。
- 重复包丢弃。窗口外旧包丢弃。缺口被后续包补齐时按序提交；等待期限到达或窗口满时推进，不能永久等待缺失包。
- 缺失音频用 A-law 静音短暂填补，时长依据相邻真实包的样本数估算，每次缺口最多 320 个样本（40 ms）。较大缺口标记为不连续，不生成数秒的填充音频，也不重复上一段语音。
- 保留真实包数、真实字节数、重复/迟到/丢包诊断的语义；新增补偿样本和重排诊断。虚拟静音不冒充真实门口机包，不推进真实包 revision。
- 每次主循环有界推进到期重排，不依赖下一包才能清空等待窗口。挂断、抢占或 generation 变化直接丢弃剩余音频。

### 发布和保留窗口

- 目标音频块为 800 个样本（100 ms）。未达到目标时，最老待发布样本等待至多 100 ms 后允许发布较短块。
- 定时导出从当前 generation 的第一批待发布样本开始计算；上一通话的导出时间不能延迟新通话首块。
- 每块最多 1,600 个样本（200 ms），对应 PCM 正文最多 3,200 字节。运行停顿造成积压时保留最近的有限音频，丢弃更旧样本并报告丢弃量，不连续重放历史语音。
- 音频计时按样本数，而非固定包数推进，兼容 128、160、192 样本载荷和短静音补偿。
- 保留最多 20 个块，均写入现有私有临时目录；不写持久存储。20 块是恢复窗口上限，不是允许浏览器堆积两秒语音。
- 保持 revision 单调、块的 previous revision 串联、原子发布和 generation 清理。失败发布不能先提交游标，重试不能重复播放已经提交的块。
- 通话结束后清除音频块、重排窗口和待发布缓存；不发布结束后的尾部语音。

### HTTP 身份与兼容性

保留 `GET /api/v1/audio/latest.wav`、`generation`、`after` 和 ETag 契约。原调用者继续可以使用旧参数。

新连续播放请求同时提供 `runtime` 和 `station_id`，并要求：

- 两个身份参数必须同时存在且合法，目标与当前 `talking` 通话精确匹配。
- 先验证通话身份，再判断是否有音频。挂断不能被混同为等待首块音频；304 空结果也必须经过身份验证并携带对应身份元数据。
- 读取文件前后均核实 runtime、station、generation；重启复用 generation 也不能放行旧音频。
- 返回经过验证的 runtime/station 身份、原 revision 元数据、采样格式与不连续信息，HA 必须校验，不只信任调用前的缓存状态。
- 身份不符返回 409；没有当前音频返回 404；暂时读失败返回 503；没有新块返回 304；格式错误返回 400。
- 新身份请求的错误增加稳定 `code`：`audio_identity_mismatch`、`audio_cursor_expired`、`audio_unavailable`、`audio_temporarily_unavailable` 或 `invalid_request`。只有游标过期可以在同一身份内重同步，身份失配必须终止；旧查询的错误格式保持兼容。
- 连续播放能力通过 `audio.pcm_stream_version = 1` 暴露。新 HA 遇到旧主程序时给出需要更新 Doorfast 的明确错误，不把秒级旧接口冒充新的低延迟链路。

此次不改变媒体模块 ABI、GVS 42 字节音频头、8 kHz 单声道 A-law、8302 端口或上行 20 ms 帧格式。

## HA：认证拉取和听众生命周期

### 三个下行命令

在现有音频 WebSocket manager 上增加以下命令；均要求已加载配置项和管理员用户，与现有麦克风权限一致：

| 命令 | 请求重点 | 返回与行为 |
| --- | --- | --- |
| `doorfast/audio/listen_start` | `config_entry_id`、必需的 `station_id`、可选 expected generation | 刷新真实状态，绑定当前通话，返回随机 `listener_id`、实际 generation、8 kHz / mono / s16le 格式；不呼叫、不打开麦克风 |
| `doorfast/audio/listen_read` | `config_entry_id`、`listener_id` | 返回下一块 base64 PCM 及 revision/不连续标记；没有新音频返回空结果；拒绝其他连接或配置项使用该 ID |
| `doorfast/audio/listen_stop` | `config_entry_id`、`listener_id` | 释放这个浏览器的下行所有权，不挂断物理通话，不停止其他听众 |

每个配置项最多四个听众；每个连接、每台门口机只允许一个活动下行所有权。开始操作、读取操作和配置项级 Doorfast 拉取分别串行化，防止重复 start 和两个读取抢同一游标。

### 共享拉取与有界消费

- 配置项级拉取器有独立游标，不修改旧 `latest_audio_chunk` 调用者的状态。多个听众共享有限的已验证块，各自持有消费游标。
- 只保留最多四块、每块最多 3,200 字节的 PCM；慢听众落后超过 300 ms 时跳到最近块，并报告不连续，不阻塞其他听众。
- 每次有效读取最多拉取一个 Doorfast 块；没有新块不重复发送上一块。停止所有听众后不再轮询桥接器。
- 新链路的 HTTP 正文读取上限为 4,096 字节；校验完整 WAV 结构、PCM 格式、正文尺寸、runtime、station、generation、revision。只有合法且不超过 3,200 字节的 PCM 才能移除 WAV 容器并送给浏览器，不以 Content-Length 声明代替真实读取上限。
- 游标过期时只对同一身份重新同步到最近块。临时失败不重发不确定音频，也不累积追赶队列。
- 音频请求使用有界超时。连续五秒无法得到有效的同身份读取结果，或听众五秒没有读取活动，释放下行所有权；304 空结果属于有效读取，不是故障。
- HA 原有状态轮询周期不变。连续音频请求自己的精确身份校验承担快速挂断/换会话检查，不能等待五秒状态轮询才识别串台。

### 与麦克风绑定

原 `doorfast/audio/start` 增加可选 `listener_id`。全双工模式必需使用该字段；backend 将麦克风 producer 与同一连接的下行 runtime/station/generation 绑定。下行开启之后发生的新通话或 daemon 重启不能让麦克风误接到替代会话。

旧 PTT 调用不传该字段时保留原行为。每个配置项仍只有一个麦克风 producer；新的听众不能抢占另一浏览器的麦克风。

挂断、runtime/generation/station 变化、HA WebSocket 断开、集成卸载与关联下行终止时，释放对应双向资源。停止使用原始 capture/listener 的身份，不把迟到清理操作发给新会话。

## 浏览器：真正播放和全双工模式

### 音频输出

- 复用 `PcmAudioPlayback` 的在途请求和 epoch 防护，接入原生 Web Audio；下行不依赖只能在安全上下文运行的 AudioWorklet。
- AudioContext 必须在用户手势中创建/恢复。将已验证的 s16le 数据转换为单声道浮点 AudioBuffer，按 8 kHz 样本时钟连续调度，不用多个 HTML audio 元素拼接 WAV。
- 以约 120 ms 缓冲开始播放，计划中的未来音频总长不超过 300 ms；超限丢弃更旧未播放块并重新同步。
- 缺块时自然静音，恢复后继续；不循环旧语音。遇到不连续标记清除未播放的旧块并重新建立短缓冲。
- 遵守浏览器实际采样率，由 Web Audio 处理输出重采样。停止时取消所有计划节点、计时器和未完成请求的输出，并关闭本卡片持有的 AudioContext。
- 迟到的读取、解码、权限或 session-open 结果不得复活已停止的播放/麦克风。

120 ms 与 300 ms 是本地播放缓冲目标和上限，不是跨公网端到端延迟承诺。网络往返延迟、设备抖动与浏览器调度需要实测。

### 卡片模式和用户反馈

扩展现有 `custom:doorfast-ptt-card`，不要求用户替换已有卡片类型：

- 默认 `mode: ptt` 保持按住说话和原有释放行为；可选 `station_id` 的旧配置保持兼容。
- `mode: duplex` 要求 `station_id`。一次点击开启收听与麦克风，持续双向传输；再次点击关闭本卡片音频，不替用户执行物理挂断。
- `mode: listen` 要求 `station_id`。只收听，永不请求麦克风。
- HTTP 上的 duplex 入口明确降为“仅收听：麦克风需要 HTTPS”，不请求麦克风、不标记为全双工。权限拒绝同样明确提示，并保留用户主动开启的收听。
- generation 不要求用户写死在仪表盘；开启时由 backend 绑定当前通话。用户显式配置 generation 时作为匹配断言，不自动跟随替代会话。
- 通话尚未建立、其他门口机占线、麦克风已被占用、旧主程序、不安全上下文和音频连接失败均提供明确的中英文提示。
- 卡片移除、配置更换、页面隐藏、窗口失焦、HA 断线、麦克风轨结束或用户停止，立即停止本卡片双向音频。恢复可见或重连后不能自动打开麦克风。
- 使用浏览器现有 echo cancellation 和 noise suppression，不新增 native 回声消除库，也不承诺所有手机/扬声器的回声效果。优先用耳机做首次验收。
- 新卡片、输出模块及 worklet 资源同时更新版本标记，避免浏览器缓存继续加载旧模块。

视频仍使用已有 station camera / WebRTC；本阶段不把 PCM 音频塞进原摄像头视频轨，也不保证音视频严格同步。

## 错误与清理原则

- 非当前通话的音频拒绝，不自动切到其他门口机。
- 短暂下行失败可有限恢复；上行保留原 producer 的不重发原则和有界批处理。
- 下行所有权失效时停止与其关联的麦克风；其他独立听众不因单个慢连接退出。
- 所有资源释放幂等。取消期间到达的 late result 只能被丢弃或释放，不能重新开始录音。
- 日志和实体属性不保存 PCM、WAV、麦克风正文、producer token、HA token 或原始媒体信令。诊断只记录身份关联、计数、错误类型、等待/丢弃量。
- 来电自动解锁及其及时挂断逻辑保持不变；挂断仍应触发音频清理。

## 分段实现与验收

按以下依赖顺序实施，保留现有工作树，不清理或重建：

1. Doorfast 接收重排、小块发布、资源上限和带身份的 HTTP 校验。
2. HA 下行 client/manager、听众游标、共享拉取、双向绑定和清理。
3. 浏览器连续输出、卡片模式、权限处理、中英文提示与缓存版本。
4. 两项目全量回归、独立代码审查、构建产物和经授权的现场验收。

各段采用先失败测试再最小实现，不以 fixture 结果代替实机双向可听性。

| 验证层 | 必须覆盖的结果 |
| --- | --- |
| C 音频测试 | 128/160/192 样本、序号回绕、有限乱序、重复和大缺口、40 ms 截止、静音上限、真实计数和 revision、generation 清理 |
| C 发布/HTTP 测试 | 首块不受上一通话延迟、小块截止、积压丢弃、20 块裁剪、原子失败、不重复发布、读前后 runtime/station 变化、旧查询兼容 |
| HA Python 测试 | 四听众上限、认证/连接所有权、共享拉取但独立游标、格式/尺寸拒绝、304 不重播、游标过期、慢听众、并发 start/read、重启复用 generation、双向清理 |
| Node 浏览器测试 | 实际 PCM 转换、连续样本调度、缓冲上限、缺块静音、迟到结果不复活、点击保持/停止、原 PTT、HTTP 仅收听、权限拒绝、失焦/隐藏/移除清理 |
| 原链路回归 | 三台视频预览、呼叫/挂断、门禁、来电自动解锁、LuCI 状态、安装包清单与集成卸载无变化 |
| 实机验收 | 逐台通话并保持至少 10 秒，确认上下行 8302 包、实际听音/说话、时延和回声；挂断后无音频任务；HTTP 测试不能冒充麦克风验收 |

实机没有可用 HTTPS 或现场听音条件时，记录未完成的验收项，不能宣称全双工已经现场通过。已验证的控制与视频行为不得以音频实验为由修改。
