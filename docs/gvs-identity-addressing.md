# GVS 室内机身份与确定性寻址

更新：2026-09-08。本文只记录用户合法持有 APK 的静态分析和既有离线抓包对照；不包含现场发包、设备配置修改或私有住宅地址。

## 结论

GVS 室内机并非依赖 DHCP 地址来表达身份。`IS:楼栋-单元-房间-分机` 被编码为六字节逻辑地址，逻辑地址又确定性地映射为业务单播 IP 和住宅组播 IP。门口机来电处理比较目标地址前五字节，同户分机号位于第六字节。

当前没有发现向门口机申请在线令牌的独立登录消息。该结论不排除门口机检查发送报文公共头字段；也不能替代 MT8157 离线后的真实来电验收。

## 六字节布局

室内机地址布局如下：

| 偏移 | 含义 | 编码 |
|---:|---|---|
| 0 | 设备类型 | 室内机为 `0x61` |
| 1 | 楼栋 | BCD |
| 2 | 单元 | BCD |
| 3 | 楼层 | BCD |
| 4 | 房间 | BCD |
| 5 | 分机 | BCD；当前 Doorfast 配置接受 1–4 |

房间字符串的百位以上部分作为楼层，末两位作为房间号。SDK 的确定性 IP 变换只接受楼层 1–63、房间 1–32。Doorfast 因此拒绝末两位大于 32 的地址，避免产生无法映射的配置。

## 单播 IP

设：

- `bu = building * 10 + unit`
- `floor` 为楼层
- `room` 为房间号
- `machine` 为分机号

则室内机业务地址为：

```text
10.(bu >> 2).(((bu & 3) << 6) | floor).(((machine - 1) << 5) | (room - 1))
```

例如公开测试地址 `IS:2-1-101-1` 映射为 `10.5.65.0`。同户分机 2、3、4 的最后一个 IP 字节依次增加 32。

实现位于 `src/gvs_identity.c` 的 `df_gvs_identity_unicast_ip()`。

## 住宅组播 IP

SDK 使用相同逻辑地址推导住宅组播地址。设：

```text
value = (bu - 1) * 2528 + 1024 + (floor - 1) * 32 + room
```

地址为：

```text
238.((value >> 16) & 255).((value >> 8) & 255).(value & 255)
```

分机号不参与该映射，因此同一户的室内终端共享组播目标。公开测试地址的结果为 `238.0.201.129`。

实现位于 `df_gvs_identity_multicast_ip()`。

## 同户终端枚举

旧 SDK 启动 IndoorManage 后生成五个候选：

- 当前分机以外的三个 `0x61` 室内机分机；
- 两个类型为 `0x62`、分机号为 1 和 2 的 MiniOS 终端。

每个候选约每 30 秒被探测一次，60 秒未刷新则在本地标记离线。随后 IndoorSyncBusiness 在同户地址范围内执行同步询问、版本比较和维护者选择。这是同户终端维护，不是门口机登录。

实现位于 `df_gvs_identity_indoor_peers()`；当前只生成地址，不发送探测报文。

## 来电定位边界

控制帧公共头为 42 字节：10 字节魔数、6 字节目的、6 字节来源、两个 8 字节字段、功能码、操作码和两字节小端载荷长度。待机来电只在目标逻辑地址前五字节等于本户时进入状态机；建立会话后再以完整来源地址关联门口机。

现有私有抓包的首个来电请求缺失，因此直接回放只看到后续应答、媒体和挂断，不能将 `accepted=0` 解释为地址公式失败。公开单元测试独立验证地址编码、单播、组播、同户枚举和非法边界；真实主机模式仍需后续发送端与 MT8157 离线验收。

