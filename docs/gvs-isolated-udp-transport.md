# 隔离 UDP 传输适配器边界

本适配器只用于本机回环或隔离测试网络，目的是验证“完整构帧 → UDP 发送 → 对端测试桩接收”的传输链路。它不是现场功能，也不证明门口机接受 Doorfast 报文。

## 硬性约束

- 仅允许固定回环地址和固定测试端口；不得接受命令行任意目标地址或任意载荷。
- 适配器不得加入正式 Doorfast APK 的 `DAEMON_SOURCES`，不得由 procd 启动。
- 发送前必须通过 `df_gvs_transport_policy_validate()`；生产配置 `passive_only=1` 必须拒绝发送。
- 测试头字段只能使用明确标记为 `synthetic` 的固定向量，不得伪装成真实认证字段。
- 每次测试必须有有界超时、有限重试和可复核的接收端日志。
- 测试结束后关闭 socket；不得修改现场路由、防火墙、桥接或 UCI 配置。

## 验收顺序

1. 在隔离虚拟机中启动固定的 UDP 测试桩。
2. 用固定合成帧触发 Doorfast 测试适配器。
3. 测试桩核对 42 字节公共头、长度、地址、功能码和操作码。
4. 测试桩回送固定确认帧，验证发送事务的成功、失败、超时和重试终态。
5. 检查 Doorfast 生产二进制未链接该适配器，`passive_only=1` 的现场配置不变。

## 尚未覆盖的内容

该适配器不能解决真实公共头字段来源、在线注册、门口机互操作、媒体协商或开锁控制。只有在取得合法协议字段和独立兼容性证据后，才能另行评审是否创建现场传输实现。

当前守护进程没有 UDP 发送入口，生产路径只使用内存发送器。因此现阶段的回环工具只能验证固定测试帧的单向 UDP 收发；不能把测试桩自收自发或内存事务成功解释为门口机确认。对端确认闭环必须等到合法字段和独立传输实现经过评审后再开发。
