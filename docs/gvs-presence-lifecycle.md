# GVS 室内终端在线维护状态机

更新：2026-09-08。范围为用户合法持有 APK 的静态分析、既有日志和 Doorfast 离线实现。本阶段不发送网络报文。

## 状态序列

```text
DOWN
  └─ start(identity)
       → WAIT_SYNC（3 秒）
       → SYNC_ASK（3 轮，500 ms）
       → SYNC_CHOOSE（3 轮，1000 ms）
       → PERIODIC（维护者每 60 秒同步；非维护者缺失两轮后接管）

stop/network loss → DOWN
network recovery  → 从 WAIT_SYNC 重新开始
```

旧 SDK 为五个同户候选设置初始倒计时 61 秒。后台每秒递减：非零且能被 30 整除时发送探测，归零时报告离线并重置为 60。收到候选响应时标记在线并重置为 60。

Doorfast 在 `src/gvs_presence.c` 中复现上述调度并产生结构化动作。被动运行服务已接入这些动作，但回调只写入 `mode=passive` 的诊断日志；当前没有 UDP socket 或真实设备发送。

## 动作与协议依据

| Doorfast 动作 | 旧 SDK 依据 | 已知协议字段 | 当前状态 |
|---|---|---|---|
| `PEER_PROBE` | IndoorDeviceBusiness 的 30 秒分支 | 功能族 `0x07`、操作码 `0x01`、载荷 `00 01` | 只生成动作 |
| `PEER_ONLINE` | 候选响应后刷新 60 秒倒计时 | 接收操作码仍需独立整理 | 本地状态事件 |
| `PEER_OFFLINE` | 倒计时归零 | 不发送 | 本地状态事件 |
| `SYNC_ASK_ACTION` | `SYNC_ASK` 第 1–3 轮 | 功能族 `0x91`、操作码 `0x01`，含版本和轮次字段 | 只生成动作 |
| `SYNC_VERSION_ASK` | `SYNC_CHOSE` 第 1–3 轮 | 功能族 `0x91`、操作码 `0x02` | 只生成动作 |
| `PERIODIC_SYNC` | 当选维护者后的 60 秒周期 | 功能族 `0x91`、操作码 `0x03`，版本加 JSON 同步数据 | 动作由同步数据层序列化 |

表中的消息类型来自静态调用链；载荷尚未全部进入 Doorfast 序列化器。尤其不能把动作生成测试等同于门口机或其他室内机已经接受报文。

## 发送端序列化进展

`src/gvs_serialize.c` 已实现通用 42 字节控制帧构造，并将以下动作转换成帧：

- 同户候选探测：`07 01 02 00 00 01`；
- 同步询问：`91 01 03 00 VV VV RR`，版本为小端，轮次为 1–3；
- 同步版本询问：`91 02 00 00`。

其中片段从功能码开始，公共头仍位于前面。完整探测帧布局为：

```text
47 56 53 47 56 53 A5 A5 A5 A5
<目的地址 6> <本机地址 6>
<RandomCode 8> <EncryptionCode 8>
07 01 02 00 00 01
```

两个 8 字节字段必须由显式回调提供。测试使用固定的合成字段，只验证布局和边界；运行程序没有内置占位字段，也没有联网发送能力。

`src/gvs_sync.c` 已补充 `91/03`：载荷前两字节为小端版本，其后为 US-ASCII JSON。`Period` 每帧最多 20 项，`Normal` 固定一项；字符串按 JSON 规则转义。同步表只接受项目自身登记的键，本地更新使版本递增，60000 后回到 1。专用序列化接口消费 `PERIODIC_SYNC` 动作，因此通用动作序列化器仍会拒绝缺少同步表的周期动作。

## 角色处理

旧 SDK 进入 `SYNC_CHOSE` 时先假定本机为同步维护者；如果收到同户终端回复，则根据同步版本和第六字节分机号决定是否放弃维护角色。

Doorfast 已提供离线入口 `df_gvs_presence_receive_sync()`，复用完整公共头解析器；两种回复均要求恰好两个载荷字节、小端版本、完整本机目的地址、同户且非本机来源。目的地址精确匹配是本实现的保守输入约束，未推定广播接收语义。

| 回复 | 生效阶段 | 状态变化 |
|---|---|---|
| `91/81` | SYNC_ASK | 本机版本归零，退出维护角色，进入 PERIODIC，从接收时间起安排 60 秒周期；不采用回复携带的版本 |
| `91/82` | SYNC_CHOOSE | 对方版本 >= 本机版本且对方分机号 < 本机时退出维护角色；不更新本机版本 |

其他阶段的合法回复不改变角色或周期截止时间。分机号比较保持 Java `aget-byte` 的有符号语义。错误输入不修改状态。调用方负责推进定时器；本入口不执行发送，也不认证公共头字段。被动运行服务已将 `91/81`、`91/82` 和 `91/03` 从通话帧中分流，并在版本变化时保存独立 UCI 状态文件；这仍不等于真实设备已经接受主机模式上线。

`91/03` 入站解析也已接入离线状态：`Normal` 采用远端版本并让位；`Period` 重置 60 秒截止和缺失计数，再按版本及分机号决定应用已登记字段或要求重发本机全量数据。所有数据和角色变化以临时副本处理，完整验证失败时不提交。非维护者连续错过两个周期后接管并立即生成周期同步动作。

## 故障边界

- 时间必须单调；倒退时间被拒绝。
- 停止后不再产生任何动作。
- 网络恢复通过重新调用 `start()`，候选在线状态和同步阶段全部重置，避免继承断网前的过期角色。
- 回调失败会停止本次推进并返回错误；调用方不能把未成功交付的动作记为已发送。
