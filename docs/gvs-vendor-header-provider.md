# GVS 厂商公共头提供器

更新：2026-09-13。

## 厂商数据依据

本实现依据 MT8157 厂商交付数据集中的：

- `docs/Snippet/014-native-encrypt.md`：`libencrypt.so`、JNI 包装、公共头调用链和四组固定向量；
- `docs/Snippet/008-protocol-dispatch.md`：普通控制帧的公共头偏移和接收校验；
- `docs/Snippet/007-sdk-registration.md`：SDK 注册与公共头使用边界。

静态调用链确认每个普通 GVS UDP 报文生成新的 8 字节随机输入，并把逐字节变换
结果写入紧随其后的 8 字节字段。它不使用 MCU 校验路径中的 TEA，也不加密业务
payload。

## 实现契约

`gvs_vendor_header` 从 `/dev/urandom` 读取恰好 8 字节。随机源读取不完整或失败时，
整帧构造失败并清空临时字段，不会退回全零头继续发送。

第二字段按厂商 ARM64 实现复刻：

```text
mask = 00 42 42 41 26 53 56 47
output[i] = ((input[i] << 1) XOR mask[i]) & FF
```

固定向量示例：

```text
input  = 00 01 02 03 04 05 06 07
output = 00 40 46 47 2e 59 5a 49
```

对厂商数据集四份 PCAP 的 UDP/8300 普通控制帧进行只读复核，共识别 1066 个公共
头；1066 个第二字段全部与各自随机字段的上述变换结果一致，未发现不匹配样本。
音频和视频使用各自的媒体头布局，不纳入这项 42 字节控制头统计。

生产运行时的主动 UDP sender 使用该提供器。`df_gvs_placeholder_header_fields`
继续只用于内存发送器和离线测试，防止测试对系统随机源产生依赖。

## 验证边界

单元测试覆盖厂商材料给出的四组 `UDP_Encrypt` 向量、公共帧绝对偏移，以及随机源
失败时的原子性。该结果证明 x86_64 实现与静态算法一致；真实门口机对报文的接受
仍需在 MT8157 离线的用户自有环境逐项确认。
