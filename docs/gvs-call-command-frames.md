# 离线接听与挂断命令

## r12 应答关联更新（2026-09-09）

`gvs_call_ack` 在模拟发送完成后保存命令快照并等待对应应答。接听命令只接受同一门口机发往本机的 `03/83` 七字节帧；第 0 字节须为 `00`，两个端口字段须与请求一致，末字节须非零。挂断命令只接受同一方向的 `03/82` 零载荷帧。完整报文必须先通过 42 字节公共头、声明长度和实际长度校验。

确认窗口由调用方显式提供；当前没有把它固化为协议常量。等待期间再次核对会话代次、对端、本机地址和允许状态。会话变化进入 CANCELLED，期限到达进入 EXPIRED，匹配帧进入 CONFIRMED；错误来源、错误方向、错误操作码、错误端口和迟到或重复帧返回错误且不确认事务。

CONFIRMED 仅表示收到了与本地请求匹配的协议应答。当前模块不改变会话状态；运行时接入时必须先让确认器观察 `03/83`，再由现有会话逻辑处理同一帧，否则会话先进入 TALKING 后会让确认器判定状态失配。`03/82` 的确认也不等同于物理门禁动作成功。

测试入口计数升至 94，覆盖直接帧和完整 49 字节报文、错误声明长度、错误来源、端口不匹配、应答过期、重复应答、挂断确认及会话代次取消。r12 的远程 APK 构建和目标虚拟机验证仍待完成。

以下保留 r11 与 r10 的阶段记录。

## r11 离线调度更新（2026-09-09）

`gvs_call_dispatch` 现可接收一条待发送命令，并通过 `df_gvs_call_memory_attempt` 调用真实序列化器记录内存帧。单槽忙碌时拒绝第二次提交，不覆盖原命令。守护进程尚未调用此入口，管理界面也未开放控制。

状态为 QUEUED、SENDING、RETRY，以及 SENT、FAILED、TIMEOUT、CANCELLED 四种终态。采用现有发送模块的 250ms 尝试期限、100ms 重试间隔和最多三次尝试，但通话调度独立维护状态，未改动候选在线回复队列。队列等待也限于 250ms；这些时间值属于项目策略，并非静态确认的 GVS 标准。

首次发送、每次重试、等待推进以及异步完成时，核对会话代次、对端地址、本机地址与动作允许状态。失配进入 CANCELLED。完成编号跨命令递增；旧编号被拒绝，编号耗尽会明确失败。时间倒退返回错误，无法容纳期限时明确超时。调用方必须串行调用且回调不可重入；会话变更后应及时推进调度，取消依赖调用方提供的最新会话。

SENT 仅表示本地模拟发送完成，不表示门口机认可或进入通话。`complete` 接口接收的是发送器的完成编号，不是线上协议应答；`03/83`、`03/82` 的应答关联、业务确认超时和会话转换仍是下一步。

测试入口：`make test`。新增测试覆盖迟到完成、重复提交、抢占取消、等待队列过期、三次失败与三次超时、编号耗尽、UINT64_MAX 附近重试终止，以及 43 字节挂断帧的内存发送。全套测试入口计数为 90；r11 远程构建与目标虚拟机验证尚待完成。

以下为 r10 的构帧基线记录。

2026-09-09：M3 首批命令构造，包版本 `0.1.0-r10`。

`gvs_call_command` 从当前会话准备接听或挂断命令，再交给公共序列化器生成内存帧。它不改变会话，不入发送队列，也没有网络发送入口。尚未实现对端确认、重试与媒体启动，所以本阶段不能作为主机模式完成的依据。

## 布局与约束

| 动作 | family/opcode | 载荷 | 总帧长度 | 允许的本地状态 |
|---|---|---|---|---|
| 接听请求 | `03/03` | `02 P1高 P1低 00 P2高 P2低 T` | 49 | RINGING |
| 挂断请求 | `03/02` | 一个调用方提供的原因字节 | 43 | PREVIEW、RINGING、TALKING |

公共头为 42 字节，载荷长度为小端；两个端口字段为大端。静态默认值为 P1=8303、P2=8302、T=120，得到 `02 20 6f 00 20 6e 78`。端口、时长参数名是当前 API 的工作解释；本阶段确认的是字节布局，媒体协商的精确用途仍待验证。原因字节保留原值，其枚举语义尚未确定。

`prepare_answer` / `prepare_hangup` 要求非零且匹配的会话代次，并要求本机和对端地址非全零。接听额外要求两个端口及 T 非零。这些是 Doorfast 的本地调用约束，不宣称等同于 APK 的所有状态分支。失败返回 `DF_ERR_INVALID` 并清空输出命令。

命令保存地址及代次快照。序列化校验类型、操作码和长度，使用已有公共头字段提供器；测试提供器只写入合成字节，不代表真实设备会接受。**序列化不重新检查当前会话**：后续队列取出、重试和应答处理必须重新核对代次，不能把准备时检查当作发送时检查。
