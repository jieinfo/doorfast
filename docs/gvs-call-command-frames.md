# 离线接听与挂断命令

2026-09-09：M3 首批命令构造，包版本 `0.1.0-r10`。

`gvs_call_command` 从当前会话准备接听或挂断命令，再交给公共序列化器生成内存帧。它不改变会话，不入发送队列，也没有网络发送入口。尚未实现对端确认、重试与媒体启动，所以本阶段不能作为主机模式完成的依据。

## 布局与约束

| 动作 | family/opcode | 载荷 | 总帧长度 | 允许的本地状态 |
|---|---|---|---|---|
| 接听请求 | `03/03` | `02 P1高 P1低 00 P2高 P2低 T` | 49 | RINGING |
| 挂断请求 | `03/02` | 一个调用方提供的原因字节 | 43 | PREVIEW、RINGING、TALKING |

公共头为 42 字节，载荷长度为小端；两个端口字段为大端。静态默认值为 P1=8303、P2=8302、T=120，得到 `02 20 6f 00 20 6e 78`。端口、时长参数名是当前 API 的工作解释；本阶段确认的是字节布局，媒体协商的精确用途仍待验证。原因字节保留原值，其枚举语义尚未确定。

`prepare_answer` / `prepare_hangup` 要求非零且匹配的会话代次，并要求本机和对端地址非全零。接听额外要求两个端口及 T 非零。这些是 Doorfast 的本地调用约束，不宣称等同于 APK 的所有状态分支。失败返回 `DF_ERR_INVALID` 并清空输出命令。

命令保存地址及代次快照。序列化校验类型、操作码和长度，使用已有公共头字段提供器；测试提供器只写入合成字节，不代表真实设备会接受。**序列化不重新检查当前会话**：后续队列取出、重试和应答处理必须重新核对代次，不能把准备时检查当作发送时检查。

## 验证与后续接入

在仓库根目录执行 `make test`。`tests/test_gvs_call_command.c` 覆盖精确接听载荷、三种活动状态挂断、会话不变、过时代次、结束状态、无效参数与失败输出清理。全套 88 个 C 测试及 ASan/UBSan 通过；7 个 Python 测试、模拟器 CLI、包清单、主程序 CLI、LuCI 状态测试通过。

下一步将命令接入模拟发送器：取出时重新核对代次，区分本地发送成功与对端确认，建立 `03/83` 接听应答及 `03/82` 挂断应答的关联，再覆盖超时、迟到应答、抢占与重复点击。`03/50` 的 busy 帧暂不当作用户拒接命令。

静态证据见 [来电控制面证据 E-004](2026-09-08_gvs-call-control-evidence.md#e-004)。远程 x86_64 APK 构建及 r10 目标系统验收尚待完成。
