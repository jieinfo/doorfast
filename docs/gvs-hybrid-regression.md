# GVS 完整会话的离线混合验证

## 本次结论

计时同步更新：TalkBackBusiness.k([B,[B,String,int) 在通话状态用
120 减去 0x57 载荷首字节设置 z，振铃相关状态用 30 减去该字节设置 A；
配合倒计时任务，表明它传递剩余秒数。接收分支先匹配当前对端。
回放现接受活动振铃/通话会话中来自当前对端、发往本机完整六字节地址、
单字节且分别位于 0..30/0..120 的同步值，重设期限。
这是对已证实值域的实现，未复刻 Java 有符号字节在异常值下的行为。
零秒立即归类为策略超时；不复活已经超时的会话。
未验证的跨分机目标、异常范围均拒绝，尚未实现请求/应答事务绑定，
所以不能排除同地址旧同步报文误关联。
0x56 的长度矛盾仍保持严格拒绝，0x57 的被动识别不依赖放宽它。

实际混合回放接受九条同步、拒绝零条；原始回放因无前置会话拒绝九条。
六次来电、四次通话、四次挂断、两次策略超时的总数未变。
测试另覆盖剩余一秒、零秒、错误对端以及 255 异常值。

后续更新：离线回放增加阶段超时策略，振铃 30 秒、进入通话后 120 秒，
这不是通用厂商常量。计时以 PCAP 时间戳为准，在处理后续记录前检查；
重传不刷新阶段起点，时间倒退记录跳过并计入 bad_time，EOF 不自动假造超时。
因此只有文件内时间推进时会清理；尚不是运行服务的后台定时器。
超时清除待处理摘机关联，并允许下一次来电创建新会话代次。
回归覆盖振铃/通话超时边界及其后的不同对端来电。

加入该策略后，同一混合 PCAP 仍为 calls=6、talking=4，
结束原因变为 ended=4、timeout=2，bad_time=0。
结束分类统计加入后，该次回放进一步显示 hangup=4、preempt=0；
即四次非超时结束均来自已捕获挂断，没有抢占事件。
下面 ended=6 是加入阶段超时前的历史结果。
此变化展示硬性分析窗口会先于某些实际挂断报文触发；
后续应结合计时同步语义评估是否调整，不能用它证明设备的实际结束时刻。

原始 incoming-three PCAP 缺少初始请求。对原始文件的临时副本补入六个
合成初始请求后，当前解析器能够串联六次来电、四次摘机通话、六次结束。
这验证当前观察逻辑在补足前置事件后的行为，不证明合成字节等于丢失报文，
也不证明独立主机互操作能力。原始文件没有修改。

## 采集方式追查

搜索范围：moogren 项目中保留的脚本、Markdown、文本记录，以及 PVE 项目记录。
案卷 timeline 仅有初始化条目，没有找到本批抓包的 tcpdump 命令或接口/过滤配置。
经典 PCAP 文件本身也没有足以恢复过滤表达式和接口名的元数据。

四份抓包包数依次为 active-three 10620、inbound-call 1604、
incoming-three 21431、session 5398。读取到的帧全部为无 VLAN 标记的 IPv4，
没有目的地址为 IPv4 多播的帧；所有记录 caplen 均等于 wirelen。
这些观察支持继续检查多播采集覆盖，但不能证明缺失的请求一定是多播，
或断言当时使用了特定过滤条件。caplen 等于 wirelen 仅排除记录级截断，
不能排除抓包前的丢失。

## 复现

在仓库根目录构建后执行，capture.pcap 为用户保留的原始 incoming-three 文件：

make -B test

## 合成与观察的来源界线

合成部分：在同一地址对的 0x81 应答序列前加入 0x01 请求；
按应答间隔超过三秒划分序列是实验启发式，不是协议定论。
请求采用静态 sendCallAsk 的十五字节载荷布局，具体可变字段取测试值；
不透明字段为零，传输地址为文档专用地址。没有还原认证字段。

保留部分：其余 PCAP 记录、原始方向与时间戳不变。
临时混合文件含原始用户数据，不能作为公开测试附件。
代码仓库中的 C 回归夹具完全合成，以固定测试地址和公开的载荷形状构造。

## 本轮代码与测试

- 同对端的振铃重传不再创建新会话代次。
- 识别匹配当前对端的单字节 0x03/0x02 挂断请求，支持两个方向；
  结束时清除待处理摘机关联。0x51/0x52 不用于挂断。
- 统计 calls、talking、ended 会话转换，accepted 保持已接受来电帧数含重传。
- 回归覆盖：及时应答、超时边界、错误对端、首次通话结束、第二次来电和重传。
  库内测试另覆盖孤立应答、错误分机、旧 generation 及重传不延长窗口。
- 本机 macOS ARM64 构建和测试通过，未进行新的 x86_64 APK 构建。

## 尚未覆盖

实时服务与回放现共用会话截止时间和接收事务；运行中捕获错误会清理会话并进行
有限退避重开。该路径已通过库内测试，尚未在 ImmortalWrt 目标机制造接口掉线验收。
媒体内容与质量、在线维护、真实设备对发送端的接受，以及相同地址的迟到报文
跨会话歧义仍未完成验证。
