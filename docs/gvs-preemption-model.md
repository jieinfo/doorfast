# GVS 离线抢占模型

这是测试目录中的抽象研究模型，不是生产会话实现，也不是设备模拟器。依据见 [静态分析报告](libencrypt-arm64-analysis.md) 的 E9–E11。模型不加载旧库、不生成协议报文、没有网络收发，也不会进入 APK 构建。

运行：在仓库根目录执行：

```sh
python3 -B -m unittest discover -s tests -p 'test_gvs_preemption_model.py' -v
```

2026-09-08：先对未实现行为运行测试，得到预期断言失败；实现后 8 项测试通过，包括有效类别的全部 25 个优先级组合。

已覆盖：重传不换代、同级及低优先级不替换、高优先级替换的事件顺序与摘机等待清除、旧来源结束消息隔离、旧本地定时任务隔离、未知类别不支持、同来源重用的线上结束消息歧义。

模型中的来源是抽象标签，类别是已分类编号；不验证原始帧、身份分类或目标房间匹配。模型无实际时间轴，不能据此声称真实倒计时、媒体停止或抓包回放已通过测试。也尚未建模摘机回复本身，只检查抢占时清除待确认标记。

对于同一来源再次使用，模型保守返回 ambiguous 并保持状态。这是研究用的不确定性标记，不是已还原的厂商策略，不应直接复制为生产结束消息处理。优先级只覆盖有效类别；未知值的保守拒绝也是独立设计策略。

下一步：将已证实的类别比较逻辑作为独立纯函数引入实际 C 测试，再考虑生产抢占事务；必须同时处理事件顺序、计时重置和旧摘机回复，不能仅放开不同来源的入口保护。

## C 比较函数（2026-09-08）

已新增 `src/gvs_priority.c` / `.h`，由实际 C 测试入口调用，暂不加入守护程序源文件列表或会话逻辑。接口明确区分 KEEP、PREEMPT 和 UNSUPPORTED；未知类别不按旧版默认分支自动赋予优先级。

`tests/test_gvs_priority.c` 使用独立的字面量期望矩阵，覆盖 25 个有效组合，以及 77 个无效参数组合（含负值、保留类别和 int 极值）。有效矩阵在未实现函数上出现 25 个预期失败，随后实现。执行完整验证：`make -B test`。

后续接入仍需增加类别来源、双事件输出和计时重置的接口测试；当前比较结果不是对来电身份的认证，也不会自行触发抢占。

## C 会话层接入（2026-09-08）

新增 `df_gvs_session_preempt`，实际调用 C 优先级函数。仅允许振铃状态、不同来源、有效且更高优先级，以及匹配当前 generation 的请求。会话代号耗尽时拒绝，避免在该接口中回绕复用。

成功输出两个带 peer 和 generation 的有序事件：旧 HANGUP、新 INCOMING_CALL；返回新的 `ring_started_ms`，清空所有旧摘机等待字段。失败保持会话不变，并清空结果。调用方必须串行访问、事先校验目标和分类，并消费完整事件序列；该接口没有网络、媒体或回调副作用。

测试先在未实现接口上观察到预期失败，随后通过实现验证：事件顺序与来源、会话换代、清理旧等待、旧来源结束消息和回复隔离、旧 generation 回调隔离、新来源完整摘机交换，以及低优先级、未知类别、同来源、过期 generation、预览/通话状态、代号耗尽和空来源的拒绝路径。

本阶段会话接口已加入本机可执行文件的链接，但观察器及回放器尚不调用它；现有生产入口行为不变。计时起点返回不等于回放计时已重置，更不等于设备上的振铃或媒体被停止。同来源跨通话的迟到报文歧义仍未解决。

下一步是扩展观察结果以承载双事件，核实并接入来源分类，再让离线回放消费新计时起点、验证旧截止时间不会终止新会话。不能在保留单事件接口的同时静默丢弃旧 HANGUP。

## 离线观察器及回放接入（2026-09-08）

新增 `df_gvs_observe_datagram_batch`，完整头与长度校验、目标房间匹配通过后才处理来电。新会话返回一个事件，同来源重传不产生新的转换事件，高优先级抢占返回旧 HANGUP、新 INCOMING_CALL 两个事件。旧单事件接口不启用抢占，避免调用方无声丢弃旧结束事件。

新增 `df_gvs_call_category` 按静态 SDK 规则分类：0x12/0x31 为类别 1，0x13/0x32 为 0，0x62 为 7，0x61 根据前五字节是否与本机相同分为 4/3。其他类型返回未知；任一抢占类别未知都拒绝。类别来自未认证的地址，不代表可信身份。首次未知来源来电的旧有被动观察行为未在本轮改变。

`df_gvs_replay_file` 现使用批量接口，按顺序消费两个事件：旧结束计入 ended，新来电计入 calls，并使用新起点重设振铃截止时间。accepted 仍含同来源重传，重传不重置起点。ended 现也包括抢占结束，不能将它一概解释为捕获到了一条挂断报文。旧来源挂断和摘机回复不能影响不同来源的新会话。

新增真实 C 路径上的测试：

- 地址分类、不同分机同房间与不同房间；
- 双事件顺序、来源和时间；重传零转换事件；
- 低优先级、未知类别、错误目标、长度矛盾和非来电消息不改变会话；
- 合成 PCAP：旧来电第 0 秒开始，第 29 秒抢占，第 30 秒旧挂断及第 31 秒旧摘机回复不结束新会话；新会话第 58 秒仍振铃，第 59 秒到期；
- 第 58 秒同来源重传或低优先级来电均不延长新截止时间。

以上测试先在未实现接口及旧回放逻辑上产生预期失败，再实现通过。完整 C 测试、本机程序构建、地址/未定义行为检测构建的 C 测试、8 项 Python 模型测试均通过。本轮没有网络发送，也没有新 x86 APK 构建；这只让离线分析具备抢占行为，不是独立主机已经上线。

残余限制：尚未检测同来源跨会话迟到报文；批量 API 由调用方提供单调时间，时间倒退检查位于回放器；拒绝的业务消息仍沿用既有 invalid 统计，不宜将其全部视为损坏报文。既有解析器未将所有操作码的最小载荷长度作为语义验证，本轮不声称覆盖该缺口。

只读审查未发现本轮阻断问题，已按建议补充初始事件的 peer/generation/时间断言、未知当前类别、同级其他来源及空闲/结束状态代号耗尽测试。历史混合回放（文档指定身份）仍得到 calls=6、talking=4、ended=4、timeout=2、sync=9；原始抓包仍没有可建立会话的初始请求。该回归不额外证明抢占的实机行为。

## 结束原因统计（2026-09-08）

离线回放新增 `hangup` 与 `preempt` 分类，保留 `ended` 兼容汇总，并维持 `ended = hangup + preempt`。`timeout` 继续单列，不计入 `ended`：它是本地回放策略导致的状态结束，不是捕获到的挂断，也不是 SDK 抢占事件。

合成抢占测试确认 `ended=1, hangup=0, preempt=1`；既有合成挂断流程确认 `ended=1, hangup=1, preempt=0`。命令行 `--inspect-pcap` 追加两个键，不删除或改名原字段，键值解析脚本可继续读取。统计分类不改变会话状态机，也不增加网络行为。
